# Помощник для Tokyo Ghoul: Break the Chains

Бот для автопрохождения **цепной кампании** на телефоне. Бои ведёт встроенный
автобой игры, а бот переходит от боя к бою:

1. на карте нажимает «Старт»;
2. в «Расстановке» нажимает «СТАРТ»;
3. в бою следит, чтобы «АВТО» был включён;
4. после победы нажимает «Нажмите, чтобы продолжить»;
5. собирает «Получить все», закрывает окно наград и баннер повышения глубины;
6. повторяет, пока не кончится стамина или лимит забегов.

**При поражении** бот останавливается и закрывает игру. **Если стамины не
хватает** (после «Старт» не открылась расстановка), бот просто останавливается.
На любом незнакомом экране он ничего не нажимает. Если такой экран висит
дольше 90 секунд, бот останавливается и сохраняет скриншот.

Бот смотрит только на экран и нажимает через ADB. В клиент игры не лезет и
трафик не трогает. Риск бана при этом не нулевой: автоматизация нарушает
правила большинства игр.

## Что нужно

- компьютер с **[uv](https://docs.astral.sh/uv/)** (Arch: `sudo pacman -S uv`).
  Python 3.11+ uv при необходимости скачает сам;
- **adb** из Android platform-tools: <https://developer.android.com/tools/releases/platform-tools>;
- телефон с включённой **отладкой по USB** и кабель (или отладка по Wi-Fi).

### Подготовка телефона

1. Настройки → О телефоне → 7 раз нажать «Номер сборки», чтобы включить режим разработчика.
2. Настройки → Для разработчиков: включить **«Отладка по USB»**.
   - Xiaomi/POCO: ещё **«Отладка по USB (настройки безопасности)»**, иначе нажатия не пройдут.
   - OnePlus/realme/OPPO: если нажатия не проходят, включи «Отключить мониторинг разрешений».
3. Там же включи **«Не выключать экран»** (при зарядке) и держи телефон на зарядке.
4. Подключи кабель и подтверди на телефоне доступ для компьютера.

По Wi-Fi (Android 11+): «Для разработчиков» → «Беспроводная отладка» →
«Подключить по коду», затем `adb pair IP:порт` и `adb connect IP:порт`.

### Установка

```bash
git clone git@github.com:xvin84/tk_btc_assistant.git
cd tk_btc_assistant
uv sync
```

`uv sync` создаёт окружение `.venv` и ставит туда зависимости из `uv.lock`.
Системный Python он не трогает. Все команды запускаются через `uv run btc-bot ...`,
активировать окружение не нужно.

adb на Linux:

- Arch: `sudo pacman -S android-tools`;
- Debian/Ubuntu: `sudo apt install adb`.

Если `adb devices` пишет `no permissions`, нужны udev-правила (в Arch пакет
`android-udev`). Потом переподключи кабель.

## Запуск

1. Открой игру на карте **цепной кампании** (где кнопка «Старт»). Активируй стамину заранее.
2. Проверь связь и распознавание:
   ```bash
   uv run btc-bot doctor
   ```
   В строке «Текущий экран» должно быть `map_start`.
3. Первый раз запусти **пробный режим**: бот ничего не нажимает, только пишет,
   что видит и что нажал бы. Пройди один забег руками и посмотри лог:
   ```bash
   uv run btc-bot run --dry-run
   ```
4. Боевой запуск:
   ```bash
   uv run btc-bot run                 # пока не кончится стамина
   uv run btc-bot run --max-runs 3    # три забега и стоп
   uv run btc-bot run --save-frames   # плюс кадр при каждой смене экрана
   ```
   Остановить можно в любой момент по Ctrl+C. Пока бот работает, телефон лучше
   не трогать.

Лог и кадры каждого запуска лежат в `logs/<дата>/`. Если что-то пошло не так,
пришли мне `bot.log` и кадр `frames/stop_*.jpg`.

Настройки (лимиты, таймауты, закрывать ли игру) — в `config.toml`.
Шаблон с пояснениями: `config.example.toml`.

## Запись скриншотов («парсер»)

Нужна, чтобы собрать экраны, которых ещё нет: поражение, диалоги, окно
нехватки стамины. Позже из неё же будет материал для своей боевой логики.

```bash
uv run btc-bot record                 # скриншот при каждом касании экрана
uv run btc-bot record --interval 2    # плюс скриншот каждые 2 секунды
uv run btc-bot record --no-taps --interval 1   # только по таймеру
uv run btc-bot snap defeat            # один скриншот текущего экрана
```

Запись идёт в `recordings/<дата>/`:

- `tap_0001.jpg`: экран за мгновение до касания;
- `annotated/tap_0001.jpg`: то же, место касания обведено;
- `taps.jsonl`: координаты касаний (экранные и рабочие).

Если кружок стоит не там, где ты нажимал, добавь `--rotation 3` (или `1`).

## Как устроено распознавание

Кадр с телефона (2780×1264) уменьшается до рабочей ширины 1280 px. В этом
масштабе вырезаны шаблоны из `templates/`: надписи и кнопки каждого экрана.
Их описание и источники лежат в `templates/manifest.json`. Правила «какой это
экран» — в `btc_bot/screens.py`.

Сейчас шаблоны вырезаны из сжатых скриншотов из Telegram (`samples/phone_1280/`).
Чтобы сделать их точнее, положи туда же полноразмерный скриншот с тем же именем
(например, `map_start.png` из `snap`) и выполни:

```bash
uv run btc-bot rebuild-templates
```

Новый шаблон, например для экрана поражения:

```bash
uv run btc-bot classify samples/device/defeat.png --scores   # что видит бот
uv run btc-bot crop samples/device/defeat.png 70 95 320 165 --name defeat_title
```

Шаблон `defeat_title` бот подхватит сам: правило для поражения уже есть.

## Проверка без телефона

```bash
uv run pytest
```

Тесты прогоняют распознавание на всех образцах. Ещё они имитируют забеги на
скриншотах: полный забег, поражение, нехватку стамины и выключенный автобой.
